# 🚀 FinvisIQ — Production Deployment Guide

This guide explains how to deploy **FinvisIQ — Personal Finance Intelligence Platform** as a production cloud application using:

- **Railway** — Spring Boot REST API
- **Netlify** — Web frontend
- **Aiven Cloud** — Managed MySQL database
- **GitHub** — Source code and continuous deployment

---

## 🏗️ Architecture Overview

```text
┌─────────────────────────────────────────────────────────────┐
│                         NETLIFY                             │
│                                                             │
│              FinvisIQ Web Frontend                          │
│              HTML / CSS / JavaScript                        │
│              Liquid Glass UI                                │
└────────────────────────────┬────────────────────────────────┘
                             │
                             │ HTTPS / REST / JSON / JWT
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                         RAILWAY                             │
│                                                             │
│              FinvisIQ Spring Boot Backend                   │
│              Java 21 / Spring Boot 3.2.5                    │
│              REST API / Authentication / Business Logic      │
└────────────────────────────┬────────────────────────────────┘
                             │
                             │ JDBC + TLS
                             │ sslMode=REQUIRED
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                     AIVEN CLOUD MYSQL                       │
│                                                             │
│                    MySQL 8.x Database                       │
│                    smart_finance_db                         │
└─────────────────────────────────────────────────────────────┘


                     DESKTOP CLIENT
                            │
                            │ HTTPS / REST / JWT
                            ▼
                    Railway Backend
                            │
                            ▼
                     Aiven MySQL
```

### Security Principle

Neither the web frontend nor the JavaFX desktop application connects directly to the production database.

The architecture is:

```text
Web Frontend ────────► Railway API ────────► Aiven MySQL
                           ▲
                           │
Desktop Client ────────────┘
```

Database credentials remain exclusively on the backend.

# 1. 🚄 Railway Backend Deployment

## Step 1 — Connect the GitHub Repository

1. Log in to Railway.
2. Create or open the existing FinvisIQ Railway project.
3. Connect the GitHub repository:

```text
FinvisIQ-Personal-Finance-Intelligence-Platform
```

4. Select the `main` branch.
5. Allow Railway to deploy from the repository.

If the Railway service is already connected to the repository, simply push changes to `main` and Railway can automatically create a new deployment.

---

## Step 2 — Configure the Backend

The backend is a Spring Boot application.

Recommended build command:

```text
mvn clean package -DskipTests
```

Recommended start command:

```text
java -jar target/smart-finance-1.0.0.jar
```

The exact JAR filename must match the artifact generated by `pom.xml`.

The application must use the Railway-provided `PORT` environment variable.

Example:

```properties
server.port=${PORT:8080}
server.address=0.0.0.0
```

This allows the application to work both locally and on Railway.

---

# 2. 🔐 Railway Environment Variables

Configure production secrets through the Railway Variables section.

Use the following structure:

| Variable       | Example Value                                                        | Purpose                 |
| -------------- | -------------------------------------------------------------------- | ----------------------- |
| `DB_URL`       | `jdbc:mysql://<AIVEN_HOST>:<PORT>/smart_finance_db?sslMode=REQUIRED` | MySQL JDBC URL          |
| `DB_USERNAME`  | `avnadmin`                                                           | Database username       |
| `DB_PASSWORD`  | `<YOUR_AIVEN_PASSWORD>`                                              | Database password       |
| `FRONTEND_URL` | `https://<your-netlify-domain>`                                      | Allowed frontend origin |
| `JWT_SECRET`   | `<YOUR_SECURE_JWT_SECRET>`                                           | JWT signing secret      |
| `PORT`         | Railway-provided                                                     | HTTP server port        |

### Example

```text
DB_URL=jdbc:mysql://<AIVEN_HOST>:<PORT>/smart_finance_db?sslMode=REQUIRED
DB_USERNAME=avnadmin
DB_PASSWORD=<YOUR_AIVEN_PASSWORD>
FRONTEND_URL=https://<your-netlify-domain>
JWT_SECRET=<YOUR_SECURE_JWT_SECRET>
```

### Important

Never replace the placeholders above with real credentials inside this file.

Production credentials must exist only in Railway's environment variables.

# 3. ☁️ Aiven MySQL Configuration

The production database is hosted on Aiven Cloud.

The backend connects using JDBC over TLS.

Example:

```text
jdbc:mysql://<AIVEN_HOST>:<AIVEN_PORT>/smart_finance_db?sslMode=REQUIRED
```

The database name used by FinvisIQ is:

```text
smart_finance_db
```

The Aiven database credentials must remain private.

---

# 4. 🌐 Generate the Railway Domain

After the backend has been successfully deployed:

1. Open the Railway service.
2. Open **Settings**.
3. Find **Networking**.
4. Generate a public domain if one does not already exist.

The resulting URL will look similar to:

```text
https://<your-service>.up.railway.app
```

Use this URL as the API base URL for the frontend and desktop application.

# 7. 🔗 Configure the Frontend API URL

The frontend must communicate with the Railway backend.

For a Vite-based frontend, configure:

```text
VITE_API_BASE_URL=https://<your-railway-domain>
```

Do not include database credentials in frontend environment variables.

The frontend should only know the public backend API URL.

### Example

```text
VITE_API_BASE_URL=https://finvisiq-backend-production.up.railway.app
```

Replace this with the actual Railway domain.

---

# 8. 🔄 SPA Routing

If the frontend is a Single Page Application, configure Netlify redirects.

Create:

```text
frontend/_redirects
```

with:

```text
/*    /index.html   200
```

Alternatively, use a Netlify configuration file:

```toml
[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

Use only the configuration appropriate for the frontend structure.

# 9. 💻 Local Backend Development

For local backend development, configure the required environment variables.

### Windows Command Prompt

```cmd

set DB_USERNAME=avnadmin
set DB_PASSWORD=<YOUR_AIVEN_PASSWORD>
```

Then start the application:

```cmd
mvnw.cmd spring-boot:run
```

Alternatively:

```cmd
mvnw.cmd clean package -DskipTests
```

Then:

```cmd
java -jar target\smart-finance-1.0.0.jar
```

For local development, the backend will normally run on:

```text
http://localhost:8080
```

unless another port is configured.


# 16. 🚨 GitHub Push Protection

GitHub may automatically block a push if it detects credentials in the repository.

If GitHub reports:

```text
GH013: Repository rule violations found
Push cannot contain secrets
```

do NOT bypass the protection.

Instead:

1. Remove the credential from the current file.
2. Remove the credential from Git history.
3. Check the entire repository for additional secrets.
4. Rotate the exposed credential.
5. Store the new credential only in Railway.
6. Push the cleaned repository.

Removing a secret from the latest version of a file is not sufficient if the secret remains in an earlier Git commit.

# 20. 📌 Important Production Rules

### Rule 1 — Database credentials stay on Railway

```text
DB_PASSWORD → Railway only
```

### Rule 2 — Frontend never receives DB credentials

```text
Netlify → Railway API
```

### Rule 3 — Desktop never receives DB credentials

```text
JavaFX → Railway API
```

### Rule 4 — HTTPS in production

```text
Netlify ──HTTPS──► Railway
JavaFX  ──HTTPS──► Railway
Railway ──TLS────► Aiven
```

### Rule 5 — Never commit secrets

```text
GitHub ≠ Secret Storage
```

Use Railway environment variables for production backend secrets.
